# Chest link v3, S3 side — the keyboard names the account, browses, shows TOTP codes

Design of 2026-09-29. Supersedes the register map of
`2026-09-29-chest-link-v2-design.md` (never flashed); keeps everything of v2
that does not depend on the layout: the press carries `(op, instance)`,
`K_CHEST_NEXT` (0x3E01) cycles the USB mode, `K_SEC_CONFIRM` counts from the
left half only, the three cases of the active mode (arrived / in flight /
fault after 8 reads). Those are on branch `chest-link-v2` (commits up to
`01699c7c`) and stay.

**Contract (authoritative):** Niphar_chest protocol v3 — design
`docs/superpowers/specs/2026-09-29-lien-v3-navigation-totp-design.md`
(`4045e13`, amended `bb656de`), constants in `main/link/link_proto.h`, vectors
in `test/test_link_proto.c` (V1..V16, R1..R3, L1, C1, generated by running
the chest's code) at `cfd7b35` or later. The rewritten `LINK_CONTRACT.md` and
the chest's reflashed commit come with the transport; the KeSp bench waits for
both.

## 1. What changes for the keyboard (Mae, 2026-09-29)

1. **The account is named.** The chest publishes the label of the operation
   it arms (ASCII printable upper case, ≤ 34 bytes) and the number of accounts
   it targets (`N` for a RESET). The prompt shows the operation, the label and
   `N CPT` when N > 1 — the owner approves an account, not a type.
2. **The keyboard browses the accounts** (names only, free) and **shows a TOTP
   code with its countdown** — only after a press, for that account.
3. **Keys**: `K_OATH_PREV` (0x3E02), `K_OATH_NEXT` (0x3E03), `K_OATH_CODE`
   (0x3E04) — three dedicated keys (Mae). Asking for a code (`K_OATH_CODE`) and
   confirming it (`K_SEC_CONFIRM`) stay two gestures.
4. **Time lives in the chest**, set by `niphar-oath set-time` over CCID (in OATH
   mode), valid until the chest reboots (i.e. until unplug). The keyboard reads
   state bit 3 (`TIME_VALID`); at 0 it shows `NO TIME` and never requests a code.

## 2. Register map v3 (64 bytes)

`0x00-0x03` magic, `0x04` version **3**, `0x05` state (bit0 SD, bit1 USB
mounted, bit2 READY, **bit3 TIME_VALID**), `0x06-0x07` pending op (LE),
`0x08-0x0B` confirm count (LE), `0x0C` instance, `0x0D` active USB mode,
`0x0E` label length (0..34; **> 34 = corrupt, even with a valid CRC**, vector
V6g), `0x0F` accounts targeted (0 none armed, 1, N for RESET), `0x10` DMA
segment kind (0 none, 1 LIST, 2 CODE), `0x11` segment number (changes AFTER
the segment is queued), `0x12-0x13` segment length (LE, ≤ 512), `0x14-0x35`
label (34 bytes, not NUL-terminated), `0x36-0x37` CRC-16/MCRF4XX over
`0x00..0x35`. Master: `0x38` confirm `0x5A`, `0x39` instance echo, `0x3A`
requested mode, `0x3B` reserved, **`0x3C` request number (doorbell, the second
master word — the chest's reclaim of `0x38` rewrites the first word)**,
`0x3D-0x3F` reserved. The mounted invariant of v2 holds.

## 3. DMA channel

- **Request** (WRDMA `0x03`, then `WR_END` `0x07`), 8 bytes fixed: command
  (`0x01` LIST, `0x02` CODE), argument (LIST: first index; CODE: account
  index), 4 reserved zeros, CRC16 over `0x00..0x05`. After the write the master
  increments `0x3C` (one byte WRBUF).
- **Response** (RDDMA `0x04`, then `INT0` `0x08`), read ONLY when `0x11`
  changed and `0x10 != 0`, length from `0x12-0x13`, into a static 512-byte
  buffer:
  - LIST: header total / count in page / first index / flags (bit0 more),
    then per account index (1), length (1), name (n), then CRC16. Decoded with
    bounds checked against the announced length; any inconsistency = corrupt.
  - CODE: index, digits (6 or 8), 8 ASCII bytes zero-padded on the left,
    seconds remaining, reserved, CRC16. The keyboard shows the LAST `digits`
    characters.
- All transactions under `rf_bus_lock`; buffers static in internal RAM.

## 4. Flows

- **Browse**: entering OATH (active mode `0x05`, READY) the keyboard sends
  `LIST(0)`; `K_OATH_NEXT/PREV` move a cursor over `total` accounts, wrapping;
  when the cursor leaves the cached page, it sends `LIST(first)` for the page
  holding it. The screen shows `i/total` and the name. No press needed.
- **Code**: `K_OATH_CODE` with TIME_VALID set sends `CODE(cursor)`; the chest
  arms `SEC_OP_OATH_CODE` and publishes the label; the prompt shows the
  CHEST'S label (register `0x14`, never the keyboard's LIST copy — an index
  that slid shows the account really targeted); `K_SEC_CONFIRM` confirms as in
  v2; the chest queues the CODE segment; the keyboard reads it and shows the
  code large with a local countdown from the seconds remaining.
- **IHM engagements** (declared in the chest's contract): a code is never shown
  without a preceding press; it disappears at the end of its window or at the
  first navigation key; it is never refreshed automatically (a new code needs a
  new press); the name list browses freely.

## 5. Screen (bottom area, left half)

Priority: prompt (pending op) > code on display > browser (OATH active) >
layer/status as today. Prompt: op label (SIGN, TOTP…), then the chest label
over up to 5 UNSCII lines of 8, then `N CPT` if N > 1, then `OK ?`. Code: the
digits in Montserrat 24 (6) or split (8), the countdown in seconds. Browser:
`i/total` and the name. `NO TIME` replaces the browser's code hint when bit 3
is clear. The chest status lines under the logo keep the v2 rules (P4 / SD /
mode in upper or lower case / ERR).

## 6. Tests

Pure and host-tested first: the v3 register parse (V1..V16 verbatim, including
V6f label byte and V6g impossible length with a valid CRC), the request
encoder (R1, R2; R3 refused if decoded), the LIST decoder (L1 plus truncated /
over-long / bad CRC / count inconsistent with the length), the CODE decoder
(C1, digits 6/8 only), the browser model (cursor wrap, page to fetch, code
display expiry, navigation hides the code), the key routing
(`K_OATH_*` absorbed, once per press). Transport by reading and on the bench.
