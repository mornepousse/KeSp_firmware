> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the left half's chest master to protocol v3: 64-byte register block with the account label, a DMA channel for LIST and CODE, a browser of the TOTP accounts on the screen, a code shown only after a press, with three dedicated keys.

**Architecture:** Pure layer first (`chest_proto` v3 registers, DMA codecs, the `chest_oath` browser model), all host-tested against the chest's own vectors; then the key gate, the screen, and the transport that glues them. Continues branch `chest-link-v2` (tasks 1-2 of the v2 plan done: gate tag, `K_CHEST_NEXT`, left-only confirm — kept; the v2 register layout in `chest_proto` is replaced here).

**Tech Stack:** ESP-IDF 5.5 spi_master half-duplex (RDBUF/WRBUF + WRDMA/WR_END + RDDMA/INT0), FreeRTOS, LVGL 8, host CMake tests.

**Spec:** `docs/superpowers/specs/2026-09-29-chest-link-v3-design.md`

## Global Constraints

- Version 3. Register block 64 bytes: `0x00-0x03` NIPH, `0x04` version, `0x05` state (bit0 SD, bit1 USB mounted, bit2 READY, bit3 TIME_VALID), `0x06-0x07` pending op LE, `0x08-0x0B` count LE, `0x0C` instance, `0x0D` active mode, `0x0E` label length (0..34, >34 = CORRUPT even with a valid CRC), `0x0F` accounts targeted, `0x10` DMA kind (0 none, 1 LIST, 2 CODE), `0x11` DMA segment number, `0x12-0x13` DMA length LE (≤ 512), `0x14-0x35` label, `0x36-0x37` CRC-16/MCRF4XX over `0x00..0x35` LE. Master: `0x38` confirm 0x5A, `0x39` echo, `0x3A` mode request, `0x3B` reserved, `0x3C` doorbell, `0x3D-0x3F` reserved.
- DMA wire commands: WRDMA `0x03` then WR_END `0x07`; RDDMA `0x04` then INT0 `0x08`. Request 8 bytes fixed (cmd, arg, 4×0, CRC over 0..5). LIST: total, count, first, flags(bit0 more), entries (index, len, name), CRC. CODE 14 bytes: index, digits (6/8), 8 ASCII zero-padded left, seconds, reserved, CRC over 0..0x0B.
- A segment is read ONLY when `0x11` changed and `0x10 != 0`; its length from `0x12`.
- Labels/names are untrusted text: bounded (≤ 34), non-printable replaced by `?`, never interpreted.
- IHM engagements: never a code without a preceding press; the code disappears at the end of its window or at the first navigation key; never refreshed automatically; the name list browses freely; the prompt shows the CHEST's label (register `0x14`), never the keyboard's LIST copy.
- Keys: `K_OATH_PREV` 0x3E02, `K_OATH_NEXT` 0x3E03, `K_OATH_CODE` 0x3E04 (in `docs/KEYCODE_MAP.md` — the keycode-map brick enforces it). Once per new press, absorbed. Not security-bound. `K_SEC_CONFIRM` rules unchanged (left only, `is_new_press` first, `chest_gate_press()` only from key_processor.c).
- Kept from v2: `CHEST_TAG`, `chest_press_matches(tag, blk, st)`, `chest_confirm_request/step(c, st, now)`, `chest_mode_next/needs_write/track/label`, the mounted invariant.
- One chip one owner (`rf_bus_lock` on every transaction), GPIO3 driven only while present, nothing new on battery, static buffers (no malloc).
- TDD, `./scripts/check.sh --fast` green per task, the full six-board check where firmware sources change, one commit per task, no push, NEVER touch `/dev/ttyUSB*` (the ESP-Prog is reserved for another project).

## Review Focus

- V6g (label length 35 with a VALID CRC) must be CORRUPT — a truncating parser would show a name the chest never composed. Task 1.
- A LIST whose entries overrun the announced length, or whose count disagrees with the bytes, must be refused, not partially shown. Task 2.
- A code must never be visible without a press, and must vanish at the end of its window and at the first navigation. Task 3 (model) and Task 5 (screen).
- The prompt must show the chest's label, not the browser's name, when an index slid. Task 5.
- `K_OATH_CODE` with TIME_VALID clear must not send a request (show NO TIME). Task 3/6.

#define CHEST_LIST_MAX_ENTRIES  32

### Task 3: `chest_oath` — the browser model (pure)

**Files:** `main/comm/chest/chest_oath.{h,c}` (new, pure), `test/test_chest_oath.c`, test registration, `main/CMakeLists.txt` base list.

**Interfaces — Produces (`chest_oath.h`):**

```c
#include "chest_dma.h"
typedef struct {
    bool     have_page;
    chest_list_t page;          /* the cached LIST page */
    uint8_t  cursor;            /* position 0..total-1 */
    bool     code_shown;
    chest_code_t code;
    uint32_t code_deadline_ms;
} chest_oath_t;

void    chest_oath_reset(chest_oath_t *o);
/* A decoded LIST page arrives: cache it, clamp the cursor to total-1 (0 when total == 0). */
void    chest_oath_on_list(chest_oath_t *o, const chest_list_t *l);
/* A navigation key: move the cursor by delta, wrapping over total; ALWAYS hides a shown code. */
void    chest_oath_nav(chest_oath_t *o, int8_t delta);
/* True when the cursor's position is outside the cached page (or no page yet):
 * *first = the position to request LIST from. */
bool    chest_oath_page_needed(const chest_oath_t *o, uint8_t *first);
/* The account under the cursor, from the cached page: name and chest index; false if not cached. */
bool    chest_oath_cursor_entry(const chest_oath_t *o, const chest_list_entry_t **e);
/* A decoded CODE arrives (after a press): show it until now + seconds*1000. */
void    chest_oath_on_code(chest_oath_t *o, const chest_code_t *c, uint32_t now_ms);
/* Visible? Hides it (for good) once the deadline passed; *secs_left = remaining whole seconds. */
bool    chest_oath_code_visible(chest_oath_t *o, uint32_t now_ms, uint8_t *secs_left);
/* The code request decision: only with TIME_VALID, READY, a cached entry under the cursor. */
bool    chest_oath_may_request_code(const chest_oath_t *o, uint8_t chest_state, uint8_t *index);
```
